### 1.3 Validation Rules

| Rule | Constraint |
|------|-----------|
| Product name | 5–200 characters, alphanumeric + spaces + basic punctuation |
| Base price | > 0, max 999,999.99 BTN |
| Cost price | ≥ 0, must be < base price for OWNED products |
| Commission rate | 0.01–0.99 for CONSIGNMENT products, null for OWNED |
| Images | At least 1 image required for ACTIVE status. Max 8 per product, max 4 per variant. |
| SKU | Unique across all products and variants. Auto-generated by platform. |
| Slug | Unique. Auto-generated. If collision, append numeric suffix. |
| Category | Required. Must reference an existing active category. |
| Variants | At least 1 variant required for products with variant options. |
| Stock | Non-negative integer. Cannot be manually set below `reservedStock`. |
| Weight | Required. Must be > 0 for shipping calculation. |
| Status transition | DRAFT → ACTIVE (requires: ≥1 image, price > 0, category set, ≥1 variant with stock > 0, weight > 0). ACTIVE → ARCHIVED (soft archives; existing orders unaffected). ARCHIVED → ACTIVE (allowed if validation passes). |

### 1.4 Workflows

**Admin Product Onboarding:**
1. Admin receives product from vendor or purchases for owned inventory.
2. Admin creates product in DRAFT status with all metadata.
3. Admin uploads professional product photos (taken by BAH photography team).
4. Admin writes artisan story and product description.
5. Admin sets pricing: base price, cost price (for margin tracking), commission rate (for consignment).
6. Admin creates variants (if applicable) with individual SKU, stock, price overrides.
7. Admin reviews and transitions to ACTIVE → product appears in storefront.

### 2.2 Stock State Machine

```
For each ProductVariant:

  available = total stock that can be ordered
  reserved  = units locked by unpaid or processing orders
  
  Physical stock = available + reserved

  On ORDER_PLACED:
    IF available >= quantity:
      available -= quantity
      reserved  += quantity
    ELSE:
      REJECT order with OUT_OF_STOCK error

  On PAYMENT_CONFIRMED:
    No stock change (already reserved)
    
  On ORDER_SHIPPED:
    reserved -= quantity
    (physical stock now reduced)

  On ORDER_CANCELLED (before shipping):
    reserved  -= quantity
    available += quantity
    (stock returned to pool)

  On REFUND_WITH_RETURN (after delivery):
    available += quantity (once item received back)
    Log as RETURN adjustment

  On ADMIN_ADJUSTMENT:
    available += adjustment (positive or negative)
    Log as ADJUSTMENT with reason
```

### 2.3 Owned vs Consignment Differences

| Aspect | Owned Inventory | Consignment Inventory |
|--------|----------------|----------------------|
| **Who owns stock** | Platform (purchased at wholesale) | Vendor (platform holds or vendor holds) |
| **Stock location** | Always at BAH warehouse | BAH warehouse OR vendor's location |
| **Stock risk** | Platform bears unsold risk | Vendor bears unsold risk |
| **Restocking** | Platform team purchases more | Admin requests vendor to send more |
| **Financial treatment** | Revenue = sale price. COGS = cost price. | Revenue = commission amount only. Vendor payout = sale price - commission. |
| **Fulfillment** | Shipped from BAH warehouse | If at warehouse: same. If at vendor: vendor ships to BAH first, then BAH ships to customer. |
| **Damage/loss** | Platform's loss | Platform liable if at warehouse. Insurance required. |

### 3.2 Order State Machine

```
                    ┌─ PAYMENT_TIMEOUT (30 min) ─→ CANCELLED
                    │
  PENDING_PAYMENT ──┤
                    │
                    └─ PAYMENT_SUCCESS ─→ CONFIRMED ──→ PROCESSING ──→ SHIPPED ──→ DELIVERED ──→ COMPLETED
                                              │              │            │            │
                                              │              │            │            └─→ RETURN_REQUESTED
                                              │              │            │                      │
                                              └──────────────┴────────────┘                      ▼
                                                     │                                    RETURN_APPROVED
                                                     ▼                                         │
                                                 CANCELLED                                     ▼
                                                     │                                    RETURNED
                                                     ▼                                         │
                                              REFUND_INITIATED                                 ▼
                                                     │                                  REFUND_INITIATED
                                                     ▼                                         │
                                                  REFUNDED                                     ▼
                                                                                           REFUNDED
```

### 3.3 Order Data Model

```
Order
├── id (UUID)
├── orderNumber (unique, human-readable, e.g., "BAH-20260420-0001")
├── customer (FK → User, nullable for guest orders)
├── guestEmail (string, for guest checkout)
├── guestName (string, for guest checkout)
├── status (ENUM — see state machine)
├── items (OrderItem[])
├── shippingAddress (embedded: street, city, state, country, postalCode, phone)
├── shippingMethod (ENUM: STANDARD_DOMESTIC, STANDARD_INTERNATIONAL, EXPRESS_INTERNATIONAL)
├── shippingCostBTN (decimal)
├── subtotalBTN (decimal — sum of item prices)
├── taxBTN (decimal — 0 for exports; applicable for domestic)
├── totalBTN (decimal — subtotal + shipping + tax)
├── displayCurrency (string, e.g., "USD")
├── displayTotal (decimal — total in customer's chosen currency at time of order)
├── exchangeRateUsed (decimal — BTN→display currency rate locked at order time)
├── referralCode (string, nullable — the referral code used)
├── referralPartner (FK → Partner, nullable)
├── referralType (ENUM: HOTEL, GUIDE, NONE)
├── paymentId (FK → Payment)
├── notes (AdminNote[] — internal)
├── cancelledAt, cancelReason
├── createdAt, updatedAt
└── version (optimistic locking)

OrderItem
├── id (UUID)
├── order (FK → Order)
├── product (FK → Product)
├── variant (FK → ProductVariant)
├── productName (snapshot at order time)
├── variantName (snapshot)
├── sku (snapshot)
├── quantity (int, ≥ 1)
├── unitPriceBTN (snapshot at order time)
├── lineTotalBTN (unitPrice × quantity)
├── sourcingType (OWNED or CONSIGNMENT — snapshot)
├── vendor (FK → Vendor, nullable — snapshot)
├── commissionRate (decimal — snapshot of rate at order time)
├── status (ENUM: PENDING, CONFIRMED, SHIPPED, DELIVERED, CANCELLED, RETURNED)
└── shippedAt, deliveredAt
```

### 3.4 Validation Rules

| Rule | Constraint |
|------|-----------|
| Minimum order value | BTN 500 (≈$6 USD). Prevents micro-orders that are unprofitable to ship. |
| Maximum order items | 20 items per order. Prevents abuse. |
| Maximum quantity per item | 10 per variant per order. Prevents stock hoarding. |
| Shipping address | Required for all non-digital products. Must include country ISO code. |
| Guest email | Required for guest checkout. Must be valid email format. Order updates sent here. |
| Cancellation window | Customer: before SHIPPED status only. Admin: any status. System: PENDING_PAYMENT after 30 minutes. |
| Price lock | Item prices locked at the moment of order creation. Price changes do not affect existing orders. |
| Referral lock | Referral attribution locked at order creation. Cannot be changed after. |

### 4.3 Validation Rules

| Rule | Constraint |
|------|-----------|
| Minimum charge | $1 USD equivalent (Stripe minimum) |
| Maximum charge | $10,000 USD equivalent per order (fraud prevention) |
| Idempotency | Same order ID always maps to same PaymentIntent. No duplicate intents per order. |
| Webhook verification | All webhooks verified using Stripe signature. Reject unverified webhooks. |
| Refund cap | Refund amount ≤ original charge amount. Cannot refund more than charged. |
| Refund window | Full refund: within 30 days of delivery. Partial: within 90 days. After: case-by-case admin decision. |
